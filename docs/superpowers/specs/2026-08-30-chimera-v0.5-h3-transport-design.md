# Chimera v0.5 HTTP/3 Transport Design

Date: 2026-08-30

## Goal

Replace the v0.4 raw-QUIC `CHIM` stream protocol with a standards-valid HTTP/3 carrier, remove the protocol-specific active-probing oracle and decoy amplification path, fix transport selection in the native mihomo client, and publish synchronized reproducible releases.

## Non-goals and security boundary

- v0.5 does not claim that QUIC has the same camouflage property as TCP/REALITY. A QUIC server cannot borrow a third-party certificate without that site's private key.
- v0.5 does not add arbitrary UDP target relay. The QUIC carrier transports TCP proxy streams.
- v0.5 does not promise immunity from DPI, QoS, blocking, traffic analysis, endpoint compromise, or a malicious proxy operator.
- Application data that requires end-to-end confidentiality still uses HTTPS, SSH, or application-level end-to-end encryption.

## Approaches considered

### 1. Basic HTTP/3 CONNECT (selected)

Each proxied TCP connection is one valid HTTP/3 CONNECT request. Authentication is an encrypted request header. After a valid 200 response, request and response DATA frames carry the bidirectional byte stream.

Advantages: standards-valid H3, small interface, supported directly by quic-go, no custom QPACK/frame implementation, and semantically correct for a TCP tunnel.

Trade-off: CONNECT is visible to the authenticated server after TLS termination. Passive observers still see only QUIC/H3 metadata.

### 2. WebTransport / Extended CONNECT

WebTransport would provide session multiplexing and datagrams but requires extra SETTINGS negotiation, session lifecycle, and additional protocol semantics. It adds complexity without improving the current TCP-only proxy requirement.

### 3. MASQUE CONNECT-IP / CONNECT-UDP

MASQUE is suitable for packet and UDP tunneling but substantially expands the implementation and threat surface. It is deferred until a separately reviewed UDP design exists.

## Architecture

The external QUIC module interface remains small:

```go
func ListenServer(ctx context.Context, cfg ServerConfig) (*Server, ServerInfo, error)
func DialClient(ctx context.Context, cfg ClientConfig) (*Client, error)
func (c *Client) DialTCP(ctx context.Context, addr *chimera.Address) (net.Conn, error)
```

`ServerConfig` owns listener address, TLS certificate source, decoy source, authentication keys, limits, and target dial policy. `ClientConfig` owns server address, certificate pin, SNI, authentication key, and timeouts. Callers do not parse HTTP/3 frames or manage replay state.

Internally the QUIC module has four focused modules:

- `Auth`: creates and validates request authentication tokens.
- `Decoy`: fetches, sanitizes, bounds, caches, and serves an ordinary HTTP response.
- `Limiter`: enforces global and per-IP request/tunnel limits.
- `Tunnel`: validates CONNECT targets, performs a bounded dial, and relays bytes after a valid H3 response.

## HTTP/3 request and tunnel flow

1. The client establishes QUIC with ALPN `h3` and mandatory SHA-256 certificate pinning.
2. The client opens an HTTP/3 request stream through `http3.ClientConn.OpenRequestStream`.
3. The client sends a basic CONNECT request whose authority is the destination `host:port`.
4. The request includes `Authorization: Bearer <token>` and a normal browser-like user agent. The header is encrypted by QUIC TLS.
5. The server parses the request through `http3.Server` and validates method, authority, timestamp, nonce, HMAC, replay state, rate limits, and egress policy.
6. On success, the server dials the target with a strict timeout, sends a valid HTTP 200 response, flushes it, obtains the H3 stream through `HTTPStreamer`, and relays bidirectionally.
7. The client reads the valid response headers. Only a 2xx response becomes a `net.Conn`; any other response is a proxy failure.

## Authentication

The installer generates a new independent 32-byte random `QUIC_PSK` and stores it in `/opt/chimera/keys.env` with mode 0600. Existing REALITY private/public keys and short IDs remain unchanged.

The derived H3 key is:

```text
HKDF-SHA256(
  ikm  = QUIC_PSK,
  salt = REALITY public key || short ID,
  info = "chimera-h3-auth-v1"
)
```

The token contains:

```text
version(1) || unix_time(8) || nonce(16) || HMAC-SHA256(derived_key, canonical_request)
```

The canonical request covers version, timestamp, nonce, method, CONNECT authority, and TLS server name. The server accepts a maximum clock skew of 60 seconds and stores accepted nonces in a strictly bounded replay cache.

Authentication failure, malformed authorization, expired timestamps, replay, unsupported methods, and forbidden targets all take the same unauthenticated response path. No `CHIM` magic or authentication-specific EOF behavior remains.

## Decoy behavior and resource limits

The decoy module fetches the configured HTTPS root page at startup and refreshes it at most once every ten minutes. It uses:

- a five-second fetch timeout;
- no redirects;
- DNS/IP egress validation before dialing;
- a 256 KiB response-body limit;
- a small allowlist of safe response headers;
- stale-cache-on-refresh-error behavior;
- a built-in bounded 404 page when no cached origin response exists.

Every unauthenticated request is served from memory. No probe request performs a new origin fetch.

The H3 server limits request headers, incoming bidirectional streams, incoming unidirectional streams, handshake time, idle time, active tunnels, and decoy concurrency. A bounded per-IP token bucket limits unauthenticated requests. Limit rejections use the same decoy-shaped response class and do not reveal authentication state.

## TLS certificates

The server supports two certificate modes:

- Preferred: user-provided CA-signed certificate and key for a domain the user controls.
- Compatibility: persisted self-signed ECDSA certificate pinned by clients. Its SAN/CN uses the configured QUIC server name rather than `chimera`.

The installer remains compatible with pinned self-signed certificates and clearly labels their active-probing limitation. It does not pretend to possess a third-party SNI certificate.

## Target and SSRF policy

CONNECT authorities must parse as a non-empty host plus port. The server resolves domains itself and rejects loopback, private, link-local, multicast, unspecified, documentation, carrier-grade NAT, and metadata destinations after resolution. Redirects are irrelevant to CONNECT and disabled in decoy fetching.

Target dial, authentication read, response write, and relay idle deadlines are explicit. A global semaphore bounds concurrent target dials and tunnels.

## Mihomo transport selection

The native adapter chooses mode before opening any transport:

- `tcp`: dial TCP/REALITY only.
- `quic`: dial HTTP/3 only; TCP reachability is irrelevant.
- `auto`: attempt QUIC with a short configurable selection timeout, then lazily dial TCP/REALITY only if QUIC fails. No speculative TCP connection is retained.

The default auto QUIC selection budget is 1200 ms. The adapter closes every partially created QUIC connection or stream on failure. Tests use injected dial functions to prove that disallowed transports are never called and losing resources are closed.

## Compatibility and configuration

The H3 carrier is protocol revision v0.5 and is intentionally incompatible with v0.3/v0.4 raw QUIC. TCP/REALITY remains compatible.

Mihomo v0.5 configuration adds:

```yaml
mode: auto
quic-fp: <sha256 certificate fingerprint>
quic-psk: <base64url 32-byte secret>
auto-quic-timeout: 1200
```

The installer preserves existing keys and port/SNI. On upgrade it generates `QUIC_PSK` only when absent, persists the certificate, and prints the new client values. Server and client must be upgraded together before selecting `quic` or `auto`.

## Testing

Core regression tests must prove:

- a standard `http3.Transport` GET receives a valid decoy response;
- valid CONNECT authentication establishes a TCP echo tunnel;
- missing, malformed, expired, replayed, and wrong-key auth all receive the same decoy response class;
- raw `CHIM` input is handled only as malformed HTTP/3, with no custom branch;
- decoy origin fetch count does not increase per probe and body size never exceeds 256 KiB;
- replay cache and concurrency maps remain hard-bounded;
- private/metadata destinations remain blocked after DNS resolution;
- certificate persistence and SAN behavior are deterministic.

Mihomo regression tests must prove:

- `mode: quic` never invokes a TCP dialer;
- `mode: tcp` never invokes a QUIC dialer;
- `auto` falls back within its configured budget;
- successful QUIC does not create or retain a TCP connection;
- all failed/losing transports are closed.

Release verification must include gofmt, unit/integration tests, race tests on Linux, vet, govulncheck, TCP/QUIC/auto E2E, standard H3 probing, invalid-auth probing, clean cross-builds, revision metadata, `vcs.modified=false` for every asset, and SHA-256 checksums.

## Release policy

Core will publish v0.5.0 and the native mihomo fork will publish a matching Chimera release only after both repositories pass the full synchronized test matrix. Release notes will call out the QUIC breaking change and will not describe the transport as REALITY-equivalent or censorship-proof.
